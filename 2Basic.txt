1. ACL = Access control list.These are nothing but the command for the set authentication and authorization limit in the redis.We can set the number of client and their authorites.For Command you can refer documentation or chatgpt.

2. Persistency Configuration = You can also set the Persistency configuation in the redis either rdb or aof or both.At the time of setting up redis server.

3. Replication = You can create the Replication of one redis instance also called master into n-number of servers called slaves but those servers need to be conneted with the master instance ip and port.You can set the configuration in the redis.confg file.In order to implement the replication the master-slave need to be persistance,means persistence configuration need to enabled either edb or aof.
All the slaves instance are read only by default , althougth we can make them write but not recommended.
If any master is crashed the you can easily promote any slace to master by did chagnes in their configuration and you also need to connect rest of the slaves to that particular slave server which get promoted to master.One think you need to keep that in mind like if the crased master revived and after that you again promot them as master and the other one to slave then the data in that server overwrites with the master so you need to firstly copy the rdb or aof file to that previously creased master and then promote it to master, so that data cannot not lost. 
You simply need to configure the replication commands in the redis instance.

4. Sentinel = It is used to automatic detect the fallover between the master-slaves isntances and automatically promote any one server to the master and the rest of them to slave, it automatically re-write the configuration.
You simply need to configure the Sentinel commands in the redis instance.

5. Clustering = It help us to horizontally scale our redis cluster.It is very similar to the master-slave architecure.But in this we need to create the clustering nodes in the same server which equally divided into master and slave like if you have 6 cluster nodes then 3 consider as the master and the rest of the consider as slave.But here the think is the slave can also read and write and all the nodes run in the same server.

It also offers:
1. pub/sub messagin queue = Redis Pub/Sub (Publish/Subscribe) is a messaging paradigm that enables real-time communication between publishers and subscribers. Publishers send messages to channels without knowing who the subscribers are, and subscribers receive messages from channels they are interested in without knowing who the publishers are. This decoupling makes Redis Pub/Sub highly scalable and suitable for dynamic network topologies

2. streaming data = Redis Streams are a powerful data structure designed for managing real-time event data. They function as an append-only log with advanced features like random access, consumer groups, and trimming strategies. Streams are ideal for use cases such as event sourcing, sensor monitoring, and notifications.Redis Streams allow efficient data insertion and retrieval. Each entry in a stream is uniquely identified by an ID, which is time-based and ensures order

3. transaction = Redis transactions allow executing a group of commands in a single, atomic operation. They ensure that all commands in the transaction are executed sequentially and isolated from other client requests. The key commands for managing transactions in Redis are MULTI, EXEC, DISCARD, and WATCH.

4. Lua scripts = In Redis, a Lua script is a small program written in the Lua programming language that runs inside the Redis server to perform complex operations atomically.
Redis embeds a Lua 5.1 interpreter, allowing you to execute scripts directly on the server using commands like EVAL or EVALSHA.
